# Проверка локальной демонстрации из чистых копий

Проверка собирает CLI из указанного публичного коммита core и интерфейс из platform 8834058357a905dc016b1a7b6101b65cb43f846c. Она проверяет запись, проверку и чтение объекта, защиту существующего файла назначения, затем API и интерфейс на импортированной исторической записи Wine. Новое обучение и сравнительные испытания не выполняются. Это не повтор оценки восьми случаев и не подтверждение переносимости или численного совпадения.

Нужны Linux, Git, CPython 3.12.15, Go 1.27.3, Node.js 24.21.0 и npm 11.19.0. Для браузерной проверки используется Playwright 1.65.0 и соответствующий Chromium revision 1254 из lockfile платформы. Для установки и сборки необходим доступ к публичным GitHub, Go modules, npm и загрузке Chromium. Система не заявляется автономной или изолированной от сети.

Запустите из копии core, указав полный SHA публичного коммита core и новый каталог вне копии репозитория. Его родитель должен существовать и не содержать символических ссылок в пути. Существующий каталог не перезаписывается.

```sh
python3 tools/verify_demo.py --core-ref FULL_PUBLIC_CORE_SHA --work /absolute/path/to/new-demo --install-browser
```

Если соответствующий Chromium уже установлен через Playwright, опустите --install-browser. Для ручной дополнительной проверки можно указать UI_CHROMIUM с абсолютным путём исполняемого файла браузера; это не заменяет проверку с версией Chromium из lockfile. На чистом Ubuntu могут понадобиться системные библиотеки Chromium: их можно установить по инструкциям Playwright до запуска проверки.

Инструмент клонирует оба публичных репозитория по HTTPS, сверяет HEAD и чистоту копий, создаёт объект, проверяет его SHA-256 и точные байты восстановленного файла и убеждается, что повторный get завершается ошибкой без изменения файла. Затем он выполняет npm ci, unit-тесты и production-сборку platform. Исторический helper platform независимо клонирует core на 5c37e250896fbb67670e7a1897853f78baec144d, сверяет Git-байты и 27 хешей свидетельств и импортирует их как caller-reported. Эта версия исторического core фиксирована внутри helper и может отличаться от core-ref, по которому собран CLI. Существуют отдельно два исходных SHA: platform использует Go-модуль core, зафиксированный в собственном go.mod, а helper - указанную историческую версию. Go-модуль platform 8834058 также закреплён на core 5c37e250896fbb67670e7a1897853f78baec144d.

Без wheelhouse семь внешних зависимостей помечены unchecked. Реальные локальные Go API и собранный интерфейс проверяются на восстановленной истории, копии с отсутствующим входом и пустом каталоге. В плане статусы runtime, execution и numerical agreement остаются unchecked. Скрипт платформы самостоятельно запускает и завершает локальные серверы. Хеши файлов исходного хранилища сравниваются до и после browser smoke. Никакие предпосылки о пользователях, аутентификации или сетевой изоляции не проверяются.

При успехе summary.json содержит SHA, хеш объекта и число файлов в проверенном хранилище. commands.log, store-before.json, store-after.json и скриншоты сохраняются в рабочем каталоге; они могут содержать локальные пути и не предназначены для автоматической публикации. Ошибка завершает команду с ненулевым статусом и оставляет каталог для диагностики. Удаление каталога выполняет владелец после проверки его содержимого.
