# Проверка локального Scientific MLOps MVP

В завершённом проходе post-amendment-v3-02 все восемь случаев достигли
функциональных критериев версии 3 протокола. Два случая S0 включали по одному
новому выполнению Wine и прошли независимый численный oracle. В шести негативных
случаях обучение не запускалось, failed-попытки зарегистрированы, исходная
история сохранилась. Это результаты одной серии на одном хосте. Свидетельства
проверены независимым Sol без повторного обучения; статус интеграции и CI
фиксируется в [задаче #26](https://github.com/m1ssha/scientific-mlops-core/issues/26).

Scientific MLOps Core предоставляет локальное хранилище объектов, каталог
снимков и запусков, CLI, сравнение записей и план восстановления. Обучение и
проверку среды выполняет внешний доверенный инструмент. Отдельная платформа
предоставляет локальный API только для чтения и интерфейс истории, сравнения и
плана; она не исполняет пайплайн. Режим рассчитан на одного пользователя без
аутентификации. ADR остаются proposed.

## Методика

[План версии 3](evaluation-plan.md) и [протокол](evaluation/protocol-v3.json)
задают S0-S3 для core и составной альтернативы Git + DVC + MLflow. Они
проверяют восстановление сохранённого C=1.0 при существующем C=2.0, удаление
входа, повреждение входа с сохранением размера и отсутствие обязательного wheel.
Исходный Wine reference импортирован как caller-reported и не является новым
обучением или проверкой текущей среды.

Версия 2 отделила функциональные критерии от вспомогательной сетевой
наблюдаемости до первых сравнительных случаев. Версия 3 введена **после
наблюдения результатов** двух остановленных серий v2. Это изменение методики,
а не выполнение исходной предварительной регистрации v2. Архивы [v1](evaluation-plan-v1.md)
и [v2](evaluation-plan-v2.md) сохранены. Серия post-amendment-v3-02 выполнена
заново по всем восьми комбинациям без объединения с прежними попытками.

Правило v3 допускает ограниченное отнесение неизвестного syscall к завершающемуся
листовому процессу только при проверенных байтах и исходниках CLI, одном exec,
однозначной временной lineage из CLONE_THREAD, нормальном завершении всей группы
и неизвестном событии в неосновном потоке после exit_group. Запуск процесса,
повторный exec или неоднозначность блокируют такое отнесение. Это операционное
допущение, а не доказательство отсутствия скрытого выполнения. При любом unknown
сетевая наблюдаемость остаётся unchecked.

Использованы core и общие Wine helpers на
5c37e250896fbb67670e7a1897853f78baec144d, platform на
8834058357a905dc016b1a7b6101b65cb43f846c, стенд на
70aedce6844b4723d7d07edd00ab54034fea381a. SHA-256 протокола v3 -
508e3891196cdedb347916235d24944fa80085e7ee48d7e4180c14966f37e82f.
Платформа не участвовала в исполнении сравнительной серии.

## Результаты восьми случаев

[Машиночитаемые результаты](../examples/evaluation/evidence/post-amendment-v3-02/results.json)
содержат стадии, результаты native-команд, общих проверок и audit. В таблице
«нет запрещённых событий» означает только результат наблюдения в этом проходе,
а не изоляцию. Во всех строках функциональный статус passed, регистрация
подтверждена и проверенная исходная история не изменилась.

| Случай | Native и общая проверка материалов | Выполнение и регистрация | Сеть |
| --- | --- | --- | --- |
| S0 core | План core и общая проверка: материалы verified | 1 обучение, oracle pass, новая запись подтверждена | unchecked |
| S0 альтернатива | DVC pull: код 0; общая проверка: verified | 1 обучение, oracle pass, запись MLflow подтверждена | unchecked |
| S1 core | План core: missing dataset; общая проверка: missing | 0 обучений, failed зарегистрирован | unchecked |
| S1 альтернатива | DVC pull: код 1; общая проверка: missing dataset | 0 обучений, failed зарегистрирован | unchecked |
| S2 core | План core: corrupt dataset; общая проверка: corrupt | 0 обучений, failed зарегистрирован | нет запрещённых событий |
| S2 альтернатива | DVC pull: код 0; общая проверка SHA-256: corrupt dataset | 0 обучений, failed зарегистрирован | нет запрещённых событий |
| S3 core | План core: missing wheel; общая проверка: missing | 0 обучений, failed зарегистрирован | unchecked |
| S3 альтернатива | DVC pull: код 1; общая проверка: missing wheel и другие нематериализованные входы | 0 обучений, failed зарегистрирован | нет запрещённых событий |

В S2 альтернативы повреждение выявила общая внешняя проверка SHA-256 после
успешного DVC pull. Данные этого случая не доказывают, что сам DVC обнаружил
повреждение. В S3 альтернативы после ошибки pull часть других материалов также
осталась нематериализованной; это не означает, что все они отсутствовали в
исходном хранилище. В негативных случаях runtime, execution и numerical остаются
unchecked, а не успешными проверками.

В каждом S0 независимый oracle сверил source и repeat по строкам, предсказаниям,
матрицам и метрикам. На 45 тестовых строках accuracy и balanced accuracy модели
составили 1 и 1; для dummy - 2/5 и 1/3 соответственно. Эти дроби относятся к
данному фиксированному разбиению. Исходные и новые raw outputs двух S0 и их
[манифест SHA-256](../examples/evaluation/evidence/post-amendment-v3-02/sha256.json)
сохранены отдельно. Численное совпадение не означает побайтового совпадения всех
файлов: UUID и времена новых запусков различаются.

Для пяти случаев сетевая наблюдаемость unchecked, для трёх трасса не показала
запрещённых событий. Это не доказательство сетевой изоляции. Общая проверка
материалов и fingerprint, oracle и управление исполнением принадлежат внешнему
коду стенда; они не являются автоматически встроенными гарантиями каждого из
сравниваемых продуктов. Связь source_run_id в MLflow - тег адаптера, а не
встроенное ограничение неизменяемого снимка.

## Предыдущие остановленные серии

Две серии v2 остановились после двух и трёх начатых случаев соответственно.
Их [индекс и хеши](evaluation/evidence-instrumentation/attempts-v2.json)
сохранены; аудиты не пересмотрены по правилу v3. В primary-02 два S0 прошли
функционально, а S1/core после ожидаемого отказа и регистрации failed остался
blocked/unchecked при итоговом аудите трассы по v2.

Первая серия v3 остановилась после шести начатых случаев: подготовка повреждения
в S2 альтернативы получила PermissionError на объекте локального DVC remote с
режимом только для чтения. DVC pull и регистрация попытки MLflow в этом случае
не были достигнуты; это не результат обнаружения повреждения. Исходные аудиты и
[сводка с хешами](../examples/evaluation/evidence/stopped-v3.json) сохранены.
Новая полная серия представлена отдельно и не объединяет эти попытки.

## Чистая демонстрация и проверки

[Инструкция демонстрации](demo.md) описывает сборку CLI и интерфейса из новых
публичных копий и проверку объекта и исторического импорта Wine, включая пустой
каталог и копию с отсутствующим входом. Локально демонстрация прошла с core
299d963ea931816fea932037b909c057aafa7629, platform 8834058357a905dc016b1a7b6101b65cb43f846c
и дополнительным Chromium revision 1248. До и после browser smoke совпали хеши
19 файлов исходного хранилища. Это исторический импорт без нового обучения, а
не повтор сравнительной серии. Отдельный [workflow](../.github/workflows/clean-demo.yml) проверяет публичный
SHA кандидата, устанавливает Chromium revision 1254 из lockfile и выполняет
инструкцию заново на Ubuntu. Локальная проверка с 1248 дополняет этот CI,
а не заменяет его; SHA и ссылки на запуски фиксируются в задаче #26.

Для стенда независимо прошли 39 синтетических тестов с locked MLflow SDK,
а также Go/Wine CI исполненного head. Обычный harness CI не устанавливает
MLflow SDK и явно пропускает один необязательный SDK-тест; этот skip не
подменяет отдельный локальный проход всех 39 тестов. Сохранённые результаты
и raw outputs независимо проверены повторным вычислением oracle без нового
обучения. Агентское ревью не является одобрением другим аккаунтом GitHub.

Обязательная интеграционная проверка включает Go test, race, vet, сборку CLI,
Wine-проверки, тесты helper и Clean public demo. CI Wine не включает отдельный
опциональный WINE_FULL_CYCLE=1 и допускает явно отмеченные несовпадения среды;
ранее в этой сессии на неизменённом runtime core локально прошли Wine9 и все
33 wine_catalog tests с WINE_FULL_CYCLE=1 и реальными wheels без skips.
Демонстрация выполняет также девять UI-тестов и production-сборку платформы.
Окончательные SHA, CI-результаты и подтверждение интеграции фиксируются в #25/#26;
непрошедшие обязательные проверки запрещают закрытие задач.

## Ограничения

Исследованы один набор данных, один пайплайн и один хост. Реконструкция базовой
ОС и установленного Python, межмашинная переносимость, GPU, масштабирование,
одновременная работа пользователей, враждебная среда и потеря питания не
исследовались. Network namespace недоступен; наблюдение syscall не является
песочницей. Серия не измеряет скорость, стоимость, удобство или статистическую
вероятность успеха и не доказывает научную новизну. Прототип и его проверка не
означают автоматического принятия архитектуры.
