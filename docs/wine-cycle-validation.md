# Проверка полного цикла Wine

10 ноября 2026 года выполнен один сквозной сценарий на одном хосте с базой
`f78357a3e2bdec1c126beeb278c514d37218331f`. Это инженерная проверка одного
зафиксированного эксперимента, а не свидетельство переносимости, обобщающей
способности или научной новизны. Использованы существующий frozen-протокол Wine v1,
CPython 3.12.15, Linux x86_64 и семь локальных wheels; новые допуски не вводились.

## Выполненный сценарий

Скрипт создал отдельную копию исходного Wine и импортировал reference с wheels в
новый каталог. Затем сохранил новый snapshot с C=2.0, новым config.json и
согласованным с ним manifest.json; этот snapshot ссылается на прежний как на
предшественника. CAS обновил ссылку latest на новый snapshot. C=2.0 — разрешённое
протоколом контрольное условие; обучение на нём в этом сценарии не выполнялось.
Одноразовая исходная копия Wine была удалена. Из нейтрального рабочего каталога
внешний инструмент повторения получил исходный run ID и создал отдельный workspace.

План указал прежние snapshot, dataset и C=1.0 при latest, указывающем на C=2.0.
Новый run имеет другой ID и operation ID, связан с исходным run через source_run_id
и использует исходный snapshot. Зафиксированы результаты: материалы **verified**,
среда до и после исполнения **passed**, исполнение **succeeded**, регистрация
**confirmed**, численное сравнение **pass**. Проверка относится к объявленному
fingerprint на этом хосте, а не ко всем возможным условиям среды.

Независимый оракул считал исходный восстановленный файл данных, test-список
сохранённого разбиения и оба файла предсказаний. Он проверил порядок row_id,
истинные классы, идентичность предсказаний модели и dummy; затем пересчитал
матрицы ошибок, support, число верных ответов, accuracy и balanced accuracy через
точные дроби и сравнил их с обоими metrics.json. На 45 строках модель дала 45
верных ответов, dummy — 18; accuracy соответственно 1 и 2/5, balanced accuracy
1 и 1/3. Проверка строго различает типы JSON и не принимает нечисловые значения.

Для отказного сценария владелец временной фикстуры удалил объект исходного dataset.
План показал missing и blocker, повторение завершилось ненулевым кодом без запуска
обучения, а каталог зарегистрировал отдельную failed-попытку с исходными snapshot
и source_run_id; sequence увеличился на одну ожидаемую операцию. Прежние записи,
receipts и байты исходных выходов остались неизменными. Владелец вернул точные
байты в фикстуру, и новый план снова показал verified. Это ручное вмешательство
в тестовую копию, а не автоматическое восстановление или repair продукта.

## Свидетельства и повторение

[Каталог свидетельств](../examples/wine_catalog/evidence/issue20/) содержит
исходные records/receipts, C=2.0 config и manifest, планы, оба diff, отчёты,
запросы регистрации, новый run, пять файлов нового результата и
[результат оракула](../examples/wine_catalog/evidence/issue20/oracle.json).
Хеши этих файлов приведены в [sha256.json](../examples/wine_catalog/evidence/issue20/sha256.json).
В missing-плане текст диагностик заменён на `[redacted diagnostic]`, поскольку
он может содержать локальные пути; код, ключ, статус и прочие поля сохранены.
Сырые выходы нового запуска не редактировались. Публикуется первый завершённый
полный сценарий, а не выбранный по качеству результат. Предшествующая попытка
завершилась ошибкой создания evidence-каталога до импорта и обучения. После неё
два отдельных запуска полного сценария прошли в автоматически удаляемых временных
каталогах как тесты; отдельно запускались тесты повторения #19 и два validation
run из workflow Wine. Это технические проверки, не серия статистических испытаний.
Wheels, venv и хранилище каталога
не публикуются. Полная временная копия фактического запуска сохранена локально в
приватном каталоге проекта; она не входит в репозиторий.

Для повторения на подходящем хосте нужны исходный репозиторий с полной Git-историей,
Go 1.27.3, заранее установленный CPython 3.12.15 и локальный набор семи wheels,
совпадающих с lock. Отпечаток среды должен совпадать с исходным reference; если
это не так, инструмент сообщает отказ, не подменяя условия. Укажите новые,
несуществующие пути scratch и evidence с существующими родительскими каталогами:

```sh
go build -o /tmp/smlops-wine-cycle ./cmd/smlops
python examples/wine_catalog/validate_cycle.py \
  --smlops /tmp/smlops-wine-cycle --python /path/to/python3.12 \
  --wheelhouse /path/to/wine-wheels --scratch /path/to/new-scratch \
  --evidence /path/to/new-evidence
```

Скрипт оставляет scratch для проверки; он содержит store и venv и не предназначен
для публикации. Выход 0 означает, что все заявленные проверки прошли. Это новая
попытка с собственными ID и временем, её файлы не обязаны побайтно совпадать с
опубликованным результатом. Исходные материалы репозитория не изменяются.

Обычные тесты `test_validate_cycle.py` проверяют оракул, повреждённые данные,
строгие типы и хеши опубликованных свидетельств. Полный сценарий — opt-in:
задайте `WINE_WHEELHOUSE` и `WINE_PYTHON` при запуске unittest для
`examples/wine_catalog`; без них он помечается skipped. На указанном хосте полный
сценарий и проверки Wine запускались с этими локальными зависимостями. Тесты
Go, race, vet и сборка CLI также выполнены локально. ADR остаются proposed.
