# Импорт исходного Wine в каталог

Этот внешний мост регистрирует уже сохранённый reference run Wine. Он не обучает
модель и не исполняет восстановленный эксперимент. Нужны Python 3, Git с
доступной в локальной истории ревизией `498bdefe3ee7d64db632910e3948c8d147738959`,
собранный CLI и существующий пустой каталог для локального хранилища. Сеть не
используется. Например, из корня репозитория:

```sh
go build -o /tmp/smlops-wine ./cmd/smlops
mkdir /tmp/wine-catalog-store
python examples/wine_catalog/import_reference.py \
  --smlops /tmp/smlops-wine --store /tmp/wine-catalog-store \
  --repository-id 0123456789abcdef0123456789abcdef \
  --wheelhouse /path/to/wine-wheels
```

Команда печатает JSON с receipts и происхождением, включая исходный UUID, phase,
ревизии набора и кода. Сохраните run `record_id` для чтения и плана:

```sh
/tmp/smlops-wine run show --store /tmp/wine-catalog-store --id RUN_ID
/tmp/smlops-wine snapshot show --store /tmp/wine-catalog-store --id SNAPSHOT_ID
/tmp/smlops-wine recovery plan --store /tmp/wine-catalog-store --run RUN_ID
```

Перед записью проверяются pinned хеши протокола, манифеста, кода и исходного
result.json, Git-байты двух файлов кода, весь набор по Wine `verify` и результаты
по `validate_output`, включая хеши выходов, предсказания, метрики и отпечаток
среды. Мост поддерживает только этот Wine v1 reference. Манифест описывает набор
из версии `2ecae3a2e2703fff651efa7d72e0e1b429670286`; код проверяется по
отдельной зафиксированной ревизии. Он не принимает произвольный pipeline.

Данные хранятся в dataset, остальные девять файлов манифеста и сам манифест —
обязательные материалы snapshot. Исходный environment.json сохранён отдельно
как обязательный descriptor, а также среди пяти исходных outputs. Полный
fingerprint отображается в conditions: скаляры напрямую, массивы и объекты как
строки JSON с сортировкой ключей, разделителями `,` и `:`, без пробелов и без
ASCII-экранирования Unicode. Все параметры config и seed разбиения типизированы.
Четыре метрики содержат определения и единицу ratio; матрицы и счётчики остаются
в сохранённом metrics.json. Наблюдения импортированы из исходного descriptor и
явно помечены как caller-reported; они не являются проверкой текущей среды.

При заданном wheelhouse проверяются и сохраняются ровно семь wheels с хешами
lock-файла как обязательные объекты. Без него семь зависимостей указываются как
внешние обязательные материалы `urn:sha256:...`; план оставляет их unchecked и
не считает материалы готовыми. Никакой загрузки пакетов мост не выполняет.
ОС и Python должны быть предоставлены отдельно; этот импорт не гарантирует
автономность, полноту условий или успешное восстановление.

Operation ID детерминирован для repository ID и трёх шагов импорта. Повтор той
же команды возвращает прежние receipts и не создаёт новые записи. Если изменить
состав запроса, например сначала импортировать без wheels, а затем повторить с
ними в тот же repository ID, CLI сообщит operation_conflict: для другого набора
используйте новый каталог и repository ID. Если процесс прервался, повторите ту
же команду с теми же параметрами. Возможны уже сохранённые объекты или первые
записи; повтор возобновит операцию, не откатывая историю. Не меняйте исходные
файлы во время импорта. Сохранённые bytes и хеши подтверждают целостность, не
доказывают происхождение или достоверность выполнения; запуск импортирован как
caller-reported. ADR остаются proposed.

Проверки моста запускаются командой:

```sh
WINE_WHEELHOUSE=/path/to/wine-wheels python -m unittest discover -s examples/wine_catalog -p 'test_*.py'
```

Без переменной `WINE_WHEELHOUSE` сценарий сохранения реальных wheels пропускается;
остальные тесты, включая вариант с внешними зависимостями и отказ неполного
wheelhouse, выполняются. CI не загружает wheels для теста моста отдельно.
